# GitHub repository presentation

These are suggested GitHub settings. Adding this document does not change the repository's About settings, topics, or Releases page.

## About description

On the repository Code page, use the gear icon beside **About** and enter:

> Local-first SOC training platform with attack simulation, log ingestion, threat detection, investigation workflows, and evidence-linked reports.

## Topics

Add these in the same About settings dialog:

- cybersecurity
- soc
- incident-response
- python
- flask
- security-monitoring
- blue-team
- security-training

Leave the website field empty unless there is a working demo you intend visitors to use. A local `127.0.0.1` address is not a public demo.

## Releases

Existing source tags are preserved. Publishing a release does not require moving or replacing them.

If publishing from an existing tag, describe the source at that tag and its known limitations. Do not imply that a tag includes documentation or fixes committed afterward. Use test results belonging to that tagged commit, with any verification limits stated clearly.

For a later release, choose a consistent version only after selecting and validating its source commit. Avoid moving older tags merely to make the newest README and an old release appear identical.

## Branches

No branches need to be removed for this documentation update. Review merged status and any unique commits before considering cleanup.
